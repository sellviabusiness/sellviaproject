# Case Study - Raw Draft

## Problem Statement

Early-stage eCommerce business owners struggle to promote their products due to limited budgets and a lack of marketing knowledge. At the same time, writers and creators in their early careers find it difficult to secure paid brand collaborations.

These two user groups face complementary problems but lack a shared platform to collaborate effectively.

## Context

Propose an affiliate-marketing platform that connects two user groups: (1) Business owners (selling digital or physical products) and (2) Content creators/influencers (bloggers, video makers, social media influencers). The problem is that new and small-scale users on both sides today lack easy, unified tools for affiliate marketing. Existing networks (like Amazon Associates, ShareASale, etc.) are complex or favor large players. Many creators find it hard to get brand deals, and small businesses struggle to set up affiliate programs. We aim to design an intuitive, streamlined UX so both parties can quickly join, list products or find products, and track commissions with minimal friction.

## Challenges

Designing this product involved balancing simplicity with system complexity while serving two different user groups.

- Designing a low-friction experience for both business owners and creators
- Reducing complexity in workflows involving onboarding, tracking, and payments
- Considering pain points from both sides without favoring one user group
- Breaking down complex processes into clear and manageable task flows

## Goal

Design a single cross-platform product that connects eCommerce business owners with writers and creators, enabling performance-based collaboration. The product should help business owners generate sales with minimal upfront cost while allowing creators to earn commissions through product promotion in a simple and transparent way.

## Outline

1. Gather domain and user context
2. Identify assumptions and hypotheses
3. Validate assumptions through research
4. Synthesize insights and define user problems
5. Translate insights into core features
6. Prioritize features for MVP
7. Reduce complexity within each feature
8. Define information architecture
9. Map key user flows
10. Design low-fidelity flows and wireframes
11. Validate designs through usability testing
12. Design high-fidelity screens

## What We Are Building

- A **web application** for each user type (business owners and creators)
- Support for **edge cases** that automate and manage most operational work
- **Mobile applications** for both user types to track sales, links, and earnings on the go
- A **marketing landing page** to explain the value proposition and onboard users

---

## Actual Design Objective

The core objective of this case study is not just feature creation, but **experience design**.

My primary goals are to:

- Design a **low-friction, smooth user experience** for both user types
- Reduce complexity across features, user flows, task flows, and onboarding journeys
- Clearly define and document workflows for business owners and creators
- Build **scalable components and a unified design system** that works consistently across web and mobile platforms
- Create detailed UX documentation covering:
    - User research methods
    - Affinity mapping and insight synthesis
    - User behavior analysis
    - Usability testing and validation
    - Design decisions and trade-offs

This case study aims to demonstrate a **real-world, system-level UX approach**, focusing on clarity, scalability, and usability rather than visual polish alone.
